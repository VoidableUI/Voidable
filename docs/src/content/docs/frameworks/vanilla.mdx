title: Vanilla
---

No framework, no adapter — just HTML and JavaScript.

## Install

```bash
npm install @voidable/ui @voidable/theme
```

## Usage

Import the component definitions as a module and use the elements in your HTML:

```html
<!DOCTYPE html>
<html data-theme="dark">
<head></head>
<body>
  <void-button variant="filled">Click me</void-button>
  <void-input aria-label="Your name" placeholder="Your name"></void-input>
  <void-alert color="info"><void-alert-description>Welcome to Voidable</void-alert-description></void-alert>

  <script type="module">
    import '@voidable/theme';
    import '@voidable/ui';
  </script>
</body>
</html>
```

### Load only what the page uses

`import '@voidable/ui'` registers every component. To fetch each component the first time its tag appears (including tags you add later), import the autoloader instead:

```html
<script type="module">
  import '@voidable/ui/autoloader';
</script>
```

Without a bundler this needs an import map, because a browser cannot resolve a bare package name; see [Loading components](/getting-started/loading/) for the import map and CDN forms and for when to prefer the full import.

## Event handling

Voidable components emit standard `CustomEvent`s. Listen with `addEventListener`:

```html
<script type="module">
  import '@voidable/ui';

  document.querySelector('void-button').addEventListener('void-click', (e) => {
    console.log('Button clicked');
  });

  document.querySelector('void-input').addEventListener('void-change', (e) => {
    console.log('Value:', e.detail.value);
  });
</script>
```

## Theme switching

Set the theme via the `data-theme` attribute on the document root:

```js
// Switch to light theme
document.documentElement.dataset.theme = 'light';

// Switch to dark theme
document.documentElement.dataset.theme = 'dark';

// Follow system preference
const prefersDark = window.matchMedia('(prefers-color-scheme: dark)');
document.documentElement.dataset.theme = prefersDark.matches ? 'dark' : 'light';

prefersDark.addEventListener('change', (e) => {
  document.documentElement.dataset.theme = e.matches ? 'dark' : 'light';
});
```

## Dynamic element creation

Create components programmatically like any DOM element:

```js
const button = document.createElement('void-button');
button.variant = 'filled';
button.textContent = 'Dynamic button';
button.addEventListener('void-click', () => alert('clicked'));
document.body.appendChild(button);
```

## Development warnings

A misspelled attribute, a value outside the allowed set or a child in the wrong parent does nothing and says nothing. Import the development entry once, in development only, and the browser console reports each mistake with the element, the valid alternatives and a "did you mean":

```js
if (import.meta.env.DEV) import('@voidable/ui/dev');
```

With an import map and no bundler, add `<script type="module">import '@voidable/ui/dev.js';</script>` to your development layout only.

It is never part of `@voidable/ui` itself, so production builds are unchanged. See [Development warnings](/getting-started/development-warnings/) for what it reports and how to make warnings throw in tests.

## Check the markup

The development warnings only see pages you open. The `voidable` tool reads the files instead, so it covers every template at once, in the editor and in CI. Install it with `curl -fsSL https://voidable.dev/install.sh | sh` (see [For AI agents](/getting-started/for-agents/#install-it)), then run:

```sh
voidable check .
```

It reports unknown elements, attributes and values, children in the wrong parent, controls with no accessible name and every form renamed in 0.8, each with what to write instead (see [Upgrading to 0.8](/guides/upgrading/)).
