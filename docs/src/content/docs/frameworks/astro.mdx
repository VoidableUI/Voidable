No adapter package needed — web components work directly in Astro templates.

## Install

```bash
npm install @voidable/ui @voidable/theme
```

## Usage

Import the component definitions in a `<script>` tag and the theme CSS globally:

```astro
---
import '@voidable/theme';
---

<html data-theme="dark">
  <head>
    <title>My App</title>
  </head>
  <body>
    <void-button variant="filled">Click me</void-button>
    <void-input aria-label="Your name" placeholder="Your name"></void-input>

    <script>
      import '@voidable/ui';

      document.querySelector('void-button')!.addEventListener('void-click', () => {
        console.log('clicked');
      });
    </script>
  </body>
</html>
```

## Gotchas

### Scoped styles don't reach Light DOM internals

Astro's scoped `<style>` tags add `data-astro-*` attributes to selectors, which won't match Light DOM component internals. Use `is:global` on style tags or import theme CSS globally:

```astro
<style is:global>
  void-button {
    --void-button-radius: 8px;
  }
</style>
```

### Curly braces in templates

Curly braces `{}` are expression delimiters in Astro templates. If you're rendering CSS or code content that contains braces, use `set:html`:

```astro
<pre><code set:html={`void-button { --void-button-radius: 8px; }`}></code></pre>
```

## Theme switching

Set the theme via the `data-theme` attribute on the root element:

```astro
<html data-theme="dark">
```

For dynamic switching, use a client-side script:

```astro
<script>
  document.documentElement.dataset.theme =
    window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
</script>
```

## Development warnings

A misspelled attribute, a value outside the allowed set or a child in the wrong parent does nothing and says nothing. Import the development entry once, in development only, and the browser console reports each mistake with the element, the valid alternatives and a "did you mean":

```js
if (import.meta.env.DEV) import('@voidable/ui/dev');
```

Put it in the same client `<script>` that imports `@voidable/ui`; Astro replaces `import.meta.env.DEV` at build time, so the production script has no trace of it.

It is never part of `@voidable/ui` itself, so production builds are unchanged. See [Development warnings](/getting-started/development-warnings/) for what it reports and how to make warnings throw in tests.
