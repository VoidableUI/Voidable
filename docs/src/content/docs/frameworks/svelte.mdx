Svelte 5 renders custom elements natively, so Svelte needs no adapter package: `@voidable/ui` and its generated typings are the whole setup. Everything below was run in a Svelte 5.59 app built with Vite and driven in a browser.

## Install

```bash
npm install @voidable/ui @voidable/theme
```

Register the elements and load the theme once, in your entry file:

```ts
// src/main.ts
import '@voidable/ui';
import '@voidable/theme';
import { mount } from 'svelte';
import App from './App.svelte';

mount(App, { target: document.getElementById('app')! });
```

## Typings

`@voidable/ui/types/svelte` registers every `<void-*>` tag with `SvelteHTMLElements`, with typed properties and typed `void-*` events. Load it from `tsconfig.json`:

```jsonc
// tsconfig.json
{
  "compilerOptions": { "types": ["svelte", "vite/client", "@voidable/ui/types/svelte"] }
}
```

Type-check with `svelte-check`. A misspelled attribute name, a value outside an attribute's type (a size that does not exist, a string where a number is expected), an `onvoid-*` event the element does not fire and a handler whose `detail` has the wrong shape are all errors.

Properties are typed under their JavaScript names, so a camelCase property such as a chart's `showValue` is written as is, not as `show-value`.

## Usage

Svelte sets a property when the element has one, so strings, booleans, numbers, arrays and objects (such as the `data` of the chart elements) keep their type. Events are `on` plus the event name, hyphens included:

```svelte
<script lang="ts">
  let name = $state('');
  let tags = $state(['design', 'ship']);
</script>

<void-button variant="filled" onvoid-click={() => console.log('clicked')}>Save</void-button>

<void-input aria-label="Your name" value={name} disabled={false} onvoid-input={(e) => (name = e.detail.value)}></void-input>

<void-tags-input aria-label="Tags" value={tags}></void-tags-input>
```

`e.detail` is typed from the element: `CustomEvent<{ value: string }>` for `void-input`, `{ value: string; checked: boolean }` for `void-checkbox`, and so on.

## Two-way binding

Svelte's `bind:` cannot be used on custom elements: `<void-input bind:value={name}>` fails to compile (`bind:value can only be used with <input>, <textarea>, <select>`). Bind the property and listen for the change event instead. This works for every control:

```svelte
<script lang="ts">
  let text = $state('a');
  let choice = $state('b');
  let agreed = $state(false);
</script>

<void-input aria-label="Comment" value={text} onvoid-input={(e) => (text = e.detail.value)}></void-input>

<void-select aria-label="Plan" value={choice} onvoid-change={(e) => (choice = e.detail.value)}>
  <select>
    <option value="a">A</option>
    <option value="b">B</option>
    <option value="c">C</option>
  </select>
</void-select>

<void-checkbox checked={agreed} onvoid-change={(e) => (agreed = e.detail.checked)}>I agree</void-checkbox>
```

## Theme

Track the colour scheme in force (resolved from `data-theme`, a theme or skin's preference and the operating system) with a store of your own:

```ts
// src/theme.ts
import { readable } from 'svelte/store';

export type Theme = 'dark' | 'light';

// The theme resolves the scheme in CSS (data-theme, then a theme or skin's preference, then the OS) and exposes it here.
const read = (): Theme =>
  getComputedStyle(document.documentElement).getPropertyValue('--void-color-scheme').trim() === 'light' ? 'light' : 'dark';

export const theme = readable<Theme>('dark', (set) => {
  set(read());
  const observer = new MutationObserver(() => set(read()));
  observer.observe(document.documentElement, { attributes: true, attributeFilter: ['data-theme'] });
  return () => observer.disconnect();
});
```

Then `{$theme}` in a template is `'dark'` or `'light'`.

If you used the removed `@voidable/ui-svelte` package, see [Migrating from the framework packages](/getting-started/migrating-from-framework-packages/).

## Development warnings

A misspelled attribute, a value outside the allowed set or a child in the wrong parent does nothing and says nothing. Import the development entry once, in development only, and the browser console reports each mistake with the element, the valid alternatives and a "did you mean":

```js
if (import.meta.env.DEV) import('@voidable/ui/dev');
```

Put it next to the `import '@voidable/ui'` in `main.ts`.

It is never part of `@voidable/ui` itself, so production builds are unchanged. See [Development warnings](/getting-started/development-warnings/) for what it reports and how to make warnings throw in tests.
