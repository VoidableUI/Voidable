Buttons have three variants of one size: at every size step they share a height and padding, so buttons in a row line up whatever their variant.

| Variant | Draws | Use for |
|---|---|---|
| `filled` | A solid fill in the accent colour | The one primary action in a view |
| `outline` (default) | A control border, no fill at rest | Secondary actions |
| `ghost` | Nothing at rest; a faint fill on hover, a stronger one when pressed | Row actions in a table, toolbars of icon buttons, the quiet action beside a primary one |

## Keyboard and click

A `void-button` activates like a native `<button>`. A mouse click, Enter (on key down) and Space (on key up) each fire one real `click` event, and one `void-click`, so anything that listens for `click` works from the keyboard too: `onClick`, `phx-click`, `wire:click`, Alpine `@click`, an overlay trigger and a form's `type="submit"` or `type="reset"`. A disabled button, or one with `aria-disabled="true"`, does nothing. A link button (an `<a href>` inside) follows its link with Enter, and Space does nothing, as on a link.

## Link buttons

An `<a href>` (or a native `<button>`) as the content makes a link that looks like a button. The inner element is the one control: the accessibility tree has one link, named by its text, one tab stop, and the `void-button` itself has no `role` and no `tabindex` and handles no keys. The whole button is the link's hit area, and the button draws its focus ring when the link has focus. The link may arrive or leave after the first render; the button follows.

```html
<void-button><a href="/docs">Read the documentation</a></void-button>
```

A link cannot be disabled, so `disabled` on a link button marks the link `aria-disabled="true"`, takes it out of the tab order (`tabindex="-1"`) and stops clicks and Enter from following it. A native `<button>` inside is disabled for real. Enabling the button takes back exactly what it wrote.

## Ghost

A ghost button has no border and no fill until it is hovered, so several of them in a row read as text, not as a row of boxes. Its label is the normal text colour, its focus ring is the same as every other button's, and in forced-colours mode it shows a border on hover and focus.

```html
<void-button variant="ghost">Open</void-button>
<void-button variant="ghost" color="error">Remove</void-button>
<void-button variant="ghost" disabled>Disabled</void-button>

<!-- A link that looks like a button: put the anchor inside -->
<void-button variant="ghost"><a href="/stations">A link</a></void-button>

<!-- Icon only: give it an aria-label; it becomes square -->
<void-button variant="ghost" aria-label="Refresh"><svg>…</svg></void-button>
```

With a `color`, a ghost button carries the colour in its label and its hover fill is a tint of that colour. Every label keeps 4.5:1 on every surface and on its own hover fill, in both colour schemes; `mise run lint:contrast` checks it.

`color` takes `default`, `error`, `warning`, `caution`, `success`, `info` and `notice`, on every variant.

## Sizes

`size` takes `sm`, `md` (default) and `lg`: the one size scale every sized component shares. The heights are the theme's control heights (28, 36 and 44px at the default density), shared with inputs and selects.

<div class="vd-example not-content">
  <div class="vd-row">
    <void-button size="sm">Small</void-button>
    <void-button>Medium</void-button>
    <void-button size="lg">Large</void-button>
    <void-input aria-label="An input, same height" placeholder="An input, same height" style="width: 14rem"></void-input>
    <void-button variant="ghost">Ghost</void-button>
  </div>
</div>

## Theming

A button has no values of its own. Its height, padding and text size come from `--void-control-*`, its radius from `--void-radius`, its colours from the accent and status tokens, so the [theme knobs](/getting-started/theming/) restyle it with everything else.
