Voidable ships {stats.elements} custom elements across {stats.components} components (parent and child elements such as `<void-accordion>` and `<void-accordion-item>` count separately; CSS-only parts such as `<void-tabs-trigger>` are not counted). All of them render in the light DOM and are styled entirely by `@voidable/theme` tokens.

Each component page is generated from the library's Custom Elements Manifest, so its attributes, events, parents and required children are what the code declares. The same data feeds `voidable ref <tag>`, the markup checker and `llms.txt`. Every page has a live example and the same markup in HTML, JSX, ERB, HEEx and Blade, produced by the `voidable gen snippet` tool.

If you are an AI agent, read [For AI agents](/getting-started/for-agents/) first. Layout and page structure come from [patterns](/patterns/overview/), not components: a shell, a page head, a section, a toolbar.

## Attributes shared across components

### Booleans

A boolean attribute means true when present and false when absent, as in HTML: `disabled="false"` is still disabled. No boolean defaults to true. Something drawn by default is turned off with a `hide-` attribute (`hide-close` on a dialog or drawer, `hide-value`, `hide-tick-min` and `hide-tick-max` on a gauge, `hide-input` on a colour picker, `hide-icon` on an error fallback, `hide-border` on a nav bar):

```html
<void-error-fallback hide-icon></void-error-fallback>
<void-nav-bar hide-border>...</void-nav-bar>
```

See [API conventions](/guides/conventions/#booleans) for the reason.

### Native text attributes

`<void-input>`, `<void-textarea>` and `<void-action-input>` forward the standard native attributes to their native control: `autocomplete`, `minlength`, `maxlength`, `inputmode`, `enterkeyhint`, `autocapitalize`, `spellcheck`, `readonly`, and (on the single-line inputs) `pattern`. `<void-input>` accepts every text-like `type`: `text`, `email`, `password`, `number`, `tel`, `url`, `search`, `date`, `datetime-local`, `month`, `time` and `week`.

```html
<void-input aria-label="Password" type="password" name="password" autocomplete="current-password" minlength="8"></void-input>
```

`minlength` and `pattern` take part in validity and form submission. They apply to what the user types, as with a native input.

### Color

Components that take a `color` accept `default`, `error`, `warning`, `caution`, `success`, `info`, `notice` and `highlight`, the same eight everywhere, each styled by the theme on every one of them. Components that take a `size` accept `sm`, `md` (default) and `lg`, the same three everywhere.
