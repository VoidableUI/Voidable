Voidable separates structure from style. Components ship with **zero visual CSS**: all appearance comes from `--void-*` CSS custom properties defined in `@voidable/theme`.

The theme is built to be rethemed by changing a handful of inputs, by a person or by an AI agent. You do not edit hundreds of tokens. You set **knobs**, and every colour, size, radius and duration is derived from them in plain CSS, in both colour schemes, with no build step.

## The knobs

Set these on `:root`. Everything else follows.

```css
:root {
  --void-accent-hue: 250;       /* blue */
  --void-accent-chroma: 0.16;   /* 0 = no accent colour (the default) */
  --void-radius: 8px;
}
```

| Knob | Default | What it changes |
|---|---|---|
| `--void-accent-hue` | `250` | Hue of the accent, as an OKLCH angle in degrees: 30 red, 60 orange, 90 yellow, 150 green, 200 teal, 250 blue, 300 purple, 350 pink. Has no effect while chroma is 0. |
| `--void-accent-chroma` | `0` | How colourful the accent is. `0` means no accent colour: primary buttons, selection and switches are the inverse of the page (white on black, black on white). `0.10` to `0.20` gives a coloured accent. Lightness is chosen for you in each scheme so the accent keeps 4.5:1 as text and under text. |
| `--void-neutral-hue` | `60` | Hue of the greys: text, borders and surfaces. |
| `--void-neutral-chroma` | `0.004` | Tint of the greys. `0` is pure grey, `0.004` is barely warm, `0.02` is clearly tinted. Capped at `0.04`. |
| `--void-page-tint` | `0` | How much of the neutral tint the page background takes, 0 to 1. `0` is a pure black or pure white page. `1` is off-white paper in light and a lifted near-black in dark. |
| `--void-contrast` | `0.2` | Strength of secondary text and control borders, 0 to 1. `0` is the softest setting that still meets WCAG AA; `1` is the strongest. Values outside the range are clamped, so no setting takes text below 4.5:1. `prefers-contrast: more` raises it to 1. |
| `--void-chrome` | `0.3` | How much the containers draw, 0 to 1: the strength of divider lines and the fill of cards and panels. `0` is faint hairlines and no fills, `1` is clear lines and visibly filled containers. |
| `--void-radius` | `4px` | Corner radius of a control. Smaller and larger radii scale from it. `0px` is square; `999px` makes controls pills (cards and dialogs stop at 24 to 32px). |
| `--void-density` | `1` | Size of things inside components: control height (36px at 1), padding and the spacing scale. `0.8` is compact, `1.15` is roomy. |
| `--void-rhythm` | `1` | Space between groups and sections of a page, independent of density. |
| `--void-font-size` | `0.875rem` | Body text size. Every other text size scales from it. |
| `--void-font-sans`, `--void-font-mono` | Inter, JetBrains Mono | Typefaces. The theme names them but ships no font files: load them yourself (for example `@fontsource-variable/inter`), or the next family in each stack is used. |
| `--void-anim-scale` | `1` | Multiplies every duration. `0` switches animation off. `prefers-reduced-motion` sets it to 0. |

The knobs are declared, with the same explanations, in `@voidable/theme/knobs` (`src/knobs.css`).

## Writing a theme

A theme is a file that sets knobs and nothing else. The package ships three as examples; each is about a dozen lines.

```css
/* themes/dune.css — warm, rounded, comfortable */
[data-void-theme="dune"] {
  --void-accent-hue: 40;
  --void-accent-chroma: 0.15;
  --void-neutral-hue: 70;
  --void-neutral-chroma: 0.025;
  --void-page-tint: 1;
  --void-contrast: 0.3;
  --void-chrome: 0.9;
  --void-radius: 10px;
  --void-density: 1.12;
  --void-rhythm: 1.1;
  --void-font-size: 0.9375rem;
}
```

```css
@import '@voidable/theme';
@import '@voidable/theme/themes/dune.css';
```

```html
<html data-void-theme="dune">
```

| Theme | Character |
|---|---|
| `void` | The default, written out: monochrome, hairlines, 4px corners, 36px controls. |
| `dune` | Warm, rounded, comfortable: a terracotta accent, sand-tinted greys on a soft page, filled containers. |
| `console` | Dense and sharp: square corners, compact controls, a signal-green accent, monospace throughout. |

Every theme works in dark and in light. You do not write a second block for light: both schemes are the same formulas.

### Contrast is checked for you

`mise run lint:contrast` evaluates the derived colours for the default knobs, for every file in `themes/`, and for the extremes of each colour knob, in both schemes. It fails if any text pair drops below 4.5:1 or any control border below 3:1, and if a theme file sets anything other than a knob.

## Theming part of a page

Knobs can be set on any element that carries the `data-void-theme` attribute (with a theme name, or empty). Everything under it is restyled:

```html
<section data-void-theme style="--void-radius: 0px; --void-density: 0.85">
  …square, compact controls in here…
</section>

<aside data-void-theme="console">…a console-themed panel…</aside>
```

Live: the first box sets two knobs inline, the second names a theme, and the third nests a light region inside a themed one. The page around them is untouched.

The attribute matters. Custom properties that are computed from other custom properties are resolved where they are declared, so the theme re-declares its derived tokens on `:root` and on every element with `data-theme`, `data-void-theme` or `data-shape`. A knob set on an element without one of those attributes changes nothing below it.

## Dark and light

Dark is the **default**. Set `data-theme` on `<html>`, or on any element, to choose a scheme explicitly; without it, the page follows the operating system.

```html
<html data-theme="light">
```

```js
function toggleTheme() {
  const current = document.documentElement.getAttribute('data-theme') ?? 'dark';
  document.documentElement.setAttribute('data-theme', current === 'dark' ? 'light' : 'dark');
}
```

Each framework guide shows a few lines that track this attribute reactively (the React adapter ships a `useTheme` hook).

## Shape

`data-shape="sharp"` on any element zeroes every radius under it; `data-shape="curvy"` restores the theme's radius. It is a preset for the radius knob.

## Type roles

Text in an interface does a small number of jobs. Each job is a **role**: a group of tokens for family, size, line height, weight, tracking, case, colour and numeric features. Components use the roles, and one attribute applies a role to your own markup:

```html
<span data-void-type="label">Stations online</span>
<span data-void-type="value">41</span> <span data-void-type="unit">of 44</span>
<span data-void-type="caption">2 in maintenance, 1 degraded</span>
```

| Role | Job | Default |
|---|---|---|
| `label` | The small quiet name of a thing: table headers, stat labels, crumbs, section meta | Mono, 11px, medium, uppercase, 0.08em tracking, secondary colour |
| `value` | The number or word a stat is about | Sans, 30px, regular, tabular figures (`data-size="sm"` and `"lg"` for 20px and 36px) |
| `unit` | Set after a value: "TB", "ms", "of 44" | 14px, secondary colour |
| `caption` | The supporting line under a value, field or row | 12px, secondary colour |
| `heading` | A section heading | 18px, medium |
| `title` | The page title | 24px, medium |
| `display` | The headline of a hero or a media surface | 36 to 64px with the viewport, line height 1.05, tight tracking |
| `lede` | The sentence under a display headline | 16px, line height 1.5, secondary colour |
| `body` | Running text | 14px, line height 1.5 |
| `code` | Ids, configuration, anything typed exactly | Mono, 13px, tabular figures |

Restyle a role once and it changes everywhere, in components and in your markup:

```css
:root {
  --void-type-label-family: var(--void-font-sans);
  --void-type-label-case: none;
  --void-type-heading-weight: var(--void-weight-bold);
}
```

Role tokens are the second layer of theming, below the knobs: reach for them when a knob cannot express what you want.

## Design values

The default look is light and airy, and it gets there with three decisions. Each is a knob, so a theme can move it.

**Control size: modest** (`--void-density`). Controls are 36px tall and every control shares the height of its size step, so a mixed row lines up:

<div class="vd-example not-content">
  <div class="vd-row">
    <void-input placeholder="Search stations" style="width: 14rem"></void-input>
    <void-select aria-label="Region"><option>All regions</option></void-select>
    <void-segmented-control value="all" aria-label="State">
      <void-segmented-control-item value="all">All</void-segmented-control-item>
      <void-segmented-control-item value="online">Online</void-segmented-control-item>
    </void-segmented-control>
    <void-button>Schedule</void-button>
    <void-button variant="filled">Add station</void-button>
  </div>
</div>

**Layout rhythm: generous** (`--void-rhythm`). The space between groups is several times the space inside them. That is where the airiness comes from, and it belongs to the page layout, not to components.

**Chrome: minimal** (`--void-chrome`). Hairlines instead of boxes, containers with a fill you can barely see, tables and lists directly on the page, and shadows only for things that overlap it. The screen below has no box in it:

## Layout rhythm

The theme provides the distances as tokens, for your page layout:

| Token | Default | Use |
|---|---|---|
| `--void-gap-tight` | 8px | A label to its control, an icon to its text |
| `--void-gap-inside` | 16px | Items in a row or a group |
| `--void-gap-stack` | 24px | Blocks stacked in a group: fields in a form |
| `--void-gap-group` | 40px | Between groups |
| `--void-gap-section` | 72px | Between sections of a page |
| `--void-gutter` | 16 to 48px | Page side padding, by viewport width |
| `--void-measure` | 34rem | Line length for running text |
| `--void-measure-page` | 72rem | Width of a page column |

The first three follow `--void-density`; the group, section and gutter distances follow `--void-rhythm`.

To scale:

      <>
        <span data-void-type="code">{`--void-gap-${gap}`}</span>
        <span class="vd-rhythm-bar" style={`width: var(--void-gap-${gap})`}></span>
        <span></span>
      </>
    ))}
  </div>
</div>

## Overriding a single token

Any derived token can still be overridden directly. Put the override on the same elements the theme derives on, so it also holds inside nested scheme or theme regions:

```css
:root, [data-theme], [data-void-theme] {
  --void-color-success: #22c55e;
}
```

Prefer a knob where one exists: an override is one value, a knob moves everything that depends on it.

## Importing the theme

Full theme (recommended):

```css
@import '@voidable/theme';
```

That resolves to one built file, `dist/void.css` (`dist/void.min.css` is the minified copy). It carries the tokens, the scoped reset, the `html` and `body` base, the type roles, every component and pattern, the pre-upgrade rules and the forced-colours rules, each in its own [cascade layer](#cascade-layers).

Parts of it, when you want less:

```css
@import '@voidable/theme/tokens';     /* primitives, knobs and everything derived, in one file */
@import '@voidable/theme/reset';      /* the reset, scoped to void-* elements */
@import '@voidable/theme/base';       /* html and body (margin, font, colour, background) */
@import '@voidable/theme/type';       /* data-void-type roles */
@import '@voidable/theme/core';       /* everything except base: touches nothing outside void-* */
@import '@voidable/theme/themes/dune.css';
```

The full theme sets `html` and `body` (margin, font, colour, background) through `base`, in the `void.reset` layer. Everything else in it matches only `void-*` elements and what they contain. Use `core` instead of the full theme if the page's `html` and `body` are yours to style.

### Per-component CSS

Every component and pattern also has its own file, generated from the same sources, so a page that uses three components need not load sixty:

```css
@import '@voidable/theme/tokens';
@import '@voidable/theme/components/button.css';
@import '@voidable/theme/components/input.css';
@import '@voidable/theme/patterns/page.css';
```

Each file declares the layer order, carries the reset for its own tags, the rules for the not-yet-defined state and the forced-colours rules for that component, and pulls in the files of any component it renders (a combobox brings its listbox parts, for instance). Always load `tokens` first or alongside: the files use the tokens but do not repeat them. `dist/exports.json` lists every file and the tags it styles.

The JavaScript side does not load CSS for you. Pair the two yourself: the components you import, or let the autoloader register, are the components whose CSS you link. Until a component's script runs, the pre-upgrade rules in its file keep the page from jumping, so the pairing is a matter of bytes, not of correctness.

## Cascade layers

The theme puts everything in named layers, declared once and in this order, lowest first:

```css
@layer theme, base, void.reset, void.tokens, void.themes, void.type,
       void.components, void.patterns, void.a11y, components, utilities;
```

The names `theme` and `base` sit below the theme's own layers, and `components` and `utilities` above them: Tailwind v4 uses exactly these, so its preflight and utilities land on either side of Voidable without configuration. Every stylesheet the theme ships repeats the statement, so the order holds whichever file the browser sees first.

### Overriding styles

Layered rules lose to unlayered ones, whatever their specificity, so your application stylesheet needs no `!important` and no selector tricks:

```css
/* app.css: not in a layer, so it wins over every void.* layer */
void-button {
  border-radius: 999px;
}

void-card {
  --void-card-padding: var(--void-space-8);
}
```

Three things follow, and they are worth knowing:

- **Put your own reset in a layer.** An unlayered reset (`* { margin: 0; padding: 0 }`, Meyer, a classic normalize) also beats the theme and will flatten component spacing. Load it into a layer below the theme instead: `@import 'reset.css' layer(base);`. Tailwind v4 preflight is already in `base`.
- **`!important` is inverted between layers.** An important rule in an earlier layer beats an important rule in a later one, and any layered important beats an unlayered one. The theme uses `!important` in only two places (reduced motion and forced colours), both in the topmost layers of its own; do not fight them with your own `!important`.
- **Order of your own layers.** To put your own code between Voidable and Tailwind utilities, name a layer after the statement: `@layer app;` placed after the theme import sits above `void.*`; place `@layer base, void.reset, ..., app` yourself only if you need something exotic.

`[data-void-theme]` and `[data-theme]` regions cascade as before: the theme files set knobs, and the tokens derive from them on `:root`, `[data-theme]` and `[data-void-theme]`, so nested regions work in any layer arrangement.

## Browser support

The derivation uses `oklch()`, `color-mix()` and `calc()` inside both: Chrome 111, Firefox 113 and Safari 16.2, all released in 2023. It does not use relative colour syntax or `light-dark()`.
