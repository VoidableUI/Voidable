## Install core packages

```bash
npm install @voidable/ui @voidable/theme
```

Lit 3 is a peer dependency of `@voidable/ui`, so your app shares a single copy of it with every Voidable package. npm, pnpm and Bun install it automatically; with Yarn run `yarn add lit` as well.

## Import the theme

Add the theme CSS to your app entry point. This loads all design tokens, primitives, and component styles:

```css
@import '@voidable/theme';
```

You can also import individual layers if you prefer granular control:

```css
@import '@voidable/theme/primitives'; /* raw color scales */
@import '@voidable/theme/tokens';     /* semantic tokens (dark/light) */
@import '@voidable/theme/reset';      /* minimal reset */
```

## Import components

Importing `@voidable/ui` registers every custom element on the page up front:

```js
import '@voidable/ui';
```

That is the simplest setup and the right one for an app that uses most of the library. Two alternatives load less:

```js
// Only the components you name, bundled with your code
import '@voidable/ui/components/button';

// Each component when its tag first appears on the page, including tags added later
import '@voidable/ui/autoloader';
```

The autoloader suits server-rendered pages (Rails, Phoenix, Laravel) and pages whose components vary by route; prefer the full import when most pages use most components. See [Loading components](/getting-started/loading/) for how each works, the import map and CDN forms, and what the page looks like before a component loads.

## Usage

Once imported, use `<void-*>` elements directly in HTML or any template:

```html
<void-button variant="filled" color="success">Save</void-button>

<void-input placeholder="Email address" type="email"></void-input>

<void-alert color="info">
  Components render in the Light DOM — your CSS applies directly.
</void-alert>
```

## Framework adapters

For framework-specific wrappers and theme utilities, install the adapter for your framework:

```bash
npm install @voidable/ui-react    # React
npm install @voidable/ui-vue      # Vue
npm install @voidable/ui-solid    # Solid
npm install @voidable/ui-svelte   # Svelte
npm install @voidable/ui-angular  # Angular
npm install @voidable/ui-hotwire  # Hotwire / Stimulus
npm install @voidable/ui-alpine   # Alpine.js
npm install @voidable/ui-liveview # Phoenix LiveView
```

See the [Frameworks](/frameworks/react/) section for usage guides.

## Without a bundler

The theme is CSS, so load it with a stylesheet link, and load the components from a CDN that resolves their `lit` dependency:

<Code lang="html" code={`<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@voidable/theme${pin}/src/index.css" />
<script type="module" src="https://esm.sh/@voidable/ui${pin}"></script>`} />

That registers every component. To load only the ones a page uses, use an import map and the autoloader instead; [Loading components](/getting-started/loading/#from-a-cdn) shows the CDN form, and `voidable install` vendors the same setup for a server that serves its own static files.

## Versions

Every Voidable package is released together under one version number{stats.version ? <> (currently <code>{stats.version}</code>)</> : null}: the npm packages, the `voidable-hotwire` gem, the `live_voidable` Hex package and the `voidable/laravel` Composer package. A release bumps all of them, even those without changes, so install the same version of each. Each adapter requires exactly the matching `@voidable/ui`, and the gem's CDN pins follow its own version.

Voidable is pre-1.0. A minor release (0.8 to 0.9) may contain breaking changes; a patch release (0.8.0 to 0.8.1) does not. Each release's notes on [GitHub](https://github.com/VoidableUI/Voidable/releases) list what changed.
