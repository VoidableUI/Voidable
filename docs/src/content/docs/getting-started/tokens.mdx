---
title: Design Tokens
---

Design tokens are the atomic values that define Voidable's visual language. Every color, spacing step, font size, shadow, radius, and motion curve is expressed as a CSS custom property prefixed with `--void-`. Components consume these tokens rather than hard-coding values, so a single override propagates everywhere.

Tokens ship in the `@voidable/theme` package. After importing it, all tokens are available as standard CSS custom properties:

```css
@import '@voidable/theme';
```

The theme is organized into three layers:

- **Primitives** (`primitives.css`) -- Fixed values with no semantic meaning: color palettes, weights, line heights, tracking, easings.
- **Knobs** (`knobs.css`) -- About a dozen inputs (accent, neutral tint, contrast, chrome, radius, density, rhythm, font size and families, motion). See [Theming](/getting-started/theming/).
- **Semantic tokens** (`tokens.css`) -- Purpose-driven tokens like `--void-color-bg` and `--void-color-text`, all derived from the knobs, in both color schemes.

Values in the tables below are the results at the default knob settings.

## Semantic color tokens

Semantic tokens carry purpose -- "the background color" rather than "stone-900". They are computed from the knobs and adapt to the color scheme set by the `data-theme` attribute.

Dark mode is the **default**. Set `data-theme="light"` on `<html>` to activate light mode.

Every grey is one **neutral foreground** color (near-white on black, near-black on white) at a different opacity over a pure page. Light mode is the same formulas with the other foreground, not a second hand-tuned set.

### Surface colors

Surfaces are opaque: the foreground mixed into the page color.

| Token | Dark | Light | Use |
|---|---|---|---|
| `--void-color-bg` | `#000` | `#fff` | The page (tinted by `--void-page-tint`) |
| `--void-color-surface` | 2.4% foreground | 2.4% foreground | Container fill: cards, panels, stats, fields. Follows `--void-chrome` (0 to 8%) |
| `--void-color-bg-secondary` | 4% | 4% | A subtle step that is always visible: stripes, row hover, wells |
| `--void-color-bg-elevated` | 7% | the page color | Things that float: menus, popovers, dialogs |
| `--void-color-bg-hover` | 8% | 8% | Hover highlight |
| `--void-color-bg-active` | 13% | 13% | Pressed, and the selected segment |
| `--void-color-bg-accent` | alias of `bg-secondary` | | Kept for compatibility |
| `--void-color-bg-overlay` | black at 70% | black at 30% | Backdrop behind dialogs and drawers |

### Text colors

| Token | Dark | Light | Contrast on the page |
|---|---|---|---|
| `--void-color-text` | foreground at 100% | 100% | about 19:1 |
| `--void-color-text-secondary` | 70% | 78% | about 9:1 |
| `--void-color-text-muted` | 57% | 65% | about 6:1 |
| `--void-color-text-tertiary` | alias of `text-muted` | | |
| `--void-color-text-disabled` | 40% | 40% | exempt (disabled) |
| `--void-color-text-on-accent` | black | white | Text on an accent or status fill |

The opacities rise with `--void-contrast`. Their floors keep 4.5:1 on every surface.

### Border colors

Two strengths with two jobs.

| Token | Dark | Light | Use |
|---|---|---|---|
| `--void-color-border` | foreground at 12% | 12% | A **divider**: separates content, decorative, follows `--void-chrome` |
| `--void-color-border-strong` | 22% | 22% | A stronger divider, and the edge of floating panels |
| `--void-color-border-control` | 44% | 52% | The boundary of an input or outline button. Keeps 3:1 on every surface; follows `--void-contrast` |
| `--void-color-border-focus` | 84% | 84% | Focus indication |

`--void-focus-ring-color`, `--void-focus-ring-width` (2px) and `--void-focus-ring-offset` (2px) are shared by every `:focus-visible` indicator.

### Accent colors

| Token | Dark | Light |
|---|---|---|
| `--void-color-accent` | near-white | near-black |
| `--void-color-accent-hover` | accent mixed 8% toward the page | |

## Border radius

Every radius scales from the `--void-radius` knob (4px by default), which is the radius of a control.

| Token | Value at 4px | Rule |
|---|---|---|
| `--void-radius-none` | `0` | |
| `--void-radius-xs` | `2px` | half the knob, at most 5px: checkboxes, small marks |
| `--void-radius-sm` | `3px` | three quarters, at most 10px |
| `--void-radius-md` | `4px` | the knob: controls |
| `--void-radius-lg` | `8px` | twice the knob, at most the knob plus 8px or 24px: cards, menus |
| `--void-radius-xl` | `16px` | four times, at most the knob plus 16px or 32px: dialogs |
| `--void-radius-full` | `9999px` | pills; `0` when the knob is 0 |

The `data-shape="sharp"` attribute on a parent element zeroes every radius under it:

```html

```

## Surfaces over imagery

Tokens for [UI over imagery](/patterns/ui-over-imagery/). The first five are inputs you may set; the rest are derived.

| Token | Default | |
|---|---|---|
| `--void-scrim-strength` | `0` | 0 to 1. `0` is the lightest scrim that keeps body text at 4.5:1 over a white image |
| `--void-scrim-fade` | `10rem` | Distance over which the scrim fades out beyond the content |
| `--void-glass-blur` | `24px` | Backdrop blur of a glass panel |
| `--void-glass-solid` | `0` | `1` makes glass a solid panel. Set to 1 automatically with `prefers-reduced-transparency` and where `backdrop-filter` is unsupported |
| `--void-media-focal` | `50% 50%` | Which point of the image survives the crop |
| `--void-scrim-alpha` | derived | Opacity of the scrim: 0.64 at strength 0, 0.94 at strength 1 |
| `--void-color-scrim` | derived | Black at `--void-scrim-alpha` |
| `--void-glass-alpha` | derived | Opacity of glass: 0.76 in light, 0.86 in dark, 1 when solid |
| `--void-color-page` | derived | The page colour itself. `--void-color-bg` is this on a page, the scrim on a media surface and the glass colour on glass |
| `--void-color-control-fill` | `transparent` | Fill of an outline control at rest. Transparent on a page; a dark translucent fill on a media surface, so a control's text does not depend on the image |
| `--void-page-inset` | derived | Inline padding that lines an element up with the `void-page` column |

## The tone system

Many Voidable components use an internal `--tone` custom property pattern for color theming. Instead of writing separate rulesets for every color variant, each component defines:

```css
void-badge {
  --tone: var(--void-color-accent);
  background: var(--tone);
}

void-badge[color="error"]   { --tone: var(--void-color-error); }
void-badge[color="warning"] { --tone: var(--void-color-warning); }
void-badge[color="success"] { --tone: var(--void-color-success); }
```

Some components derive additional tones for subtle backgrounds and borders:

```css
void-alert {
  --tone: var(--void-color-accent);
  --tone-subtle: color-mix(in srgb, var(--tone) var(--void-tone-tint), transparent);
  --tone-border: color-mix(in srgb, var(--tone) 36%, transparent);

  background: var(--tone-subtle);
  border: 1px solid var(--tone-border);
}
```

You set the tone from HTML using the `color` attribute:

```html
<void-badge color="error">3</void-badge>
<void-stat color="success">+12%</void-stat>
```

The available `color` values are: `error`, `warning`, `success`, `info`, `notice`, and `highlight`. The default (no attribute) uses `--void-color-accent`.

## Using tokens in custom CSS

Reference any token as a standard CSS custom property:

```css
.my-card {
  background: var(--void-color-bg-elevated);
  border: 1px solid var(--void-color-border);
  border-radius: var(--void-radius-md);
  padding: var(--void-space-4);
  font-family: var(--void-font-sans);
  font-size: var(--void-text-sm);
  color: var(--void-color-text);
  box-shadow: var(--void-shadow-md);
  transition: background var(--void-duration-normal) var(--void-ease-out);
}

.my-card:hover {
  background: var(--void-color-bg-hover);
}
```

Tokens compose naturally. Build a status banner using semantic colors:

```css
.status-banner {
  padding: var(--void-space-3) var(--void-space-4);
  border-radius: var(--void-radius-sm);
  font-size: var(--void-text-sm);
  font-weight: var(--void-weight-medium);
  line-height: var(--void-leading-normal);
}

.status-banner.error {
  background: var(--void-color-error-subtle);
  color: var(--void-color-error);
}

.status-banner.success {
  background: var(--void-color-success-subtle);
  color: var(--void-color-success);
}
```

Restyle a subtree by setting knobs on an element that carries `data-void-theme`:

```html
<section data-void-theme style="--void-accent-hue: 250; --void-accent-chroma: 0.16">…</section>
```

Every Voidable component inside it picks up the new accent, with hover, tint and text-on-accent colors derived to match. See [Theming](/getting-started/theming/).
