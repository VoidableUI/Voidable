`<void-description-list>` shows labels and their values: the details of a record. It wraps a native `<dl>`, so the pairing of each name with its value is in the markup for a screen reader, and the pattern only lays it out.

export const rows = `
<void-description-list>
  <dl>
    <div><dt>Region</dt><dd>Arctic</dd></div>
    <div><dt>Position</dt><dd>78.23° N, 15.39° E</dd></div>
    <div><dt>Antenna</dt><dd>7.3 m</dd></div>
    <div><dt>Site code</dt><dd data-void-type="code">SVB-1</dd></div>
  </dl>
</void-description-list>`;

export const rowsErb = `
<void-description-list>
  <dl>
    <div><dt>Region</dt><dd><%= @station.region %></dd></div>
    <div><dt>Position</dt><dd><%= @station.coordinates %></dd></div>
    <div><dt>Antenna</dt><dd><%= @station.antenna_diameter %> m</dd></div>
    <div><dt>Site code</dt><dd data-void-type="code"><%= @station.code %></dd></div>
  </dl>
</void-description-list>`;

export const rowsJsx = `
<void-description-list>
  <dl>
    {details.map(([name, value]) => (
      <div key={name}>
        <dt>{name}</dt>
        <dd>{value}</dd>
      </div>
    ))}
  </dl>
</void-description-list>`;

<Example html={rows} erb={rowsErb} jsx={rowsJsx} />

Each pair is a `<div>` holding a `<dt>` and a `<dd>`; HTML allows that grouping inside a `<dl>`, and it is what lets a pair be one row or one cell. Every `<dt>` is set as a [label](/patterns/labels/). A value that is an identifier takes `data-void-type="code"`.

## Values that start on one line

By default a value sits at the end of its row, which suits numbers and short codes that are compared down their right edge. `justify="start"` starts every value on one line after a label column instead, for values that are read: sentences, links, a state. The label column is 12rem wide (never more than 40% of the list; set `--void-description-list-label-width` to change it), so two lists on a page line up with each other, and a longer label wraps inside it.

export const start = `
<void-description-list justify="start">
  <dl>
    <div><dt>Operator</dt><dd>Kongsberg Satellite Services</dd></div>
    <div><dt>State</dt><dd><void-state color="success">Online</void-state></dd></div>
    <div><dt>Notes</dt><dd>Closed to visitors from November to February; deliveries by arrangement.</dd></div>
  </dl>
</void-description-list>`;

export const startErb = `
<void-description-list justify="start">
  <dl>
    <div><dt>Operator</dt><dd><%= @station.operator %></dd></div>
    <div><dt>State</dt><dd><void-state color="<%= state_color(@station) %>"><%= @station.state.humanize %></void-state></dd></div>
    <div><dt>Notes</dt><dd><%= @station.notes %></dd></div>
  </dl>
</void-description-list>`;

export const startJsx = `
<void-description-list justify="start">
  <dl>
    <div><dt>Operator</dt><dd>{station.operator}</dd></div>
    <div><dt>State</dt><dd><void-state color={station.stateColor}>{station.state}</void-state></dd></div>
    <div><dt>Notes</dt><dd>{station.notes}</dd></div>
  </dl>
</void-description-list>`;

## As a grid

`layout="grid"` puts the label over the value and the pairs side by side, for the summary at the top of a record. `columns` is 1 to 4; below 48rem it is two.

export const grid = `
<void-description-list layout="grid" columns="4">
  <dl>
    <div><dt>Region</dt><dd>Arctic</dd></div>
    <div><dt>Antenna</dt><dd>7.3 m</dd></div>
    <div><dt>Bands</dt><dd>S, X, Ka</dd></div>
    <div><dt>Uptime</dt><dd>99.98%</dd></div>
    <div><dt>Passes today</dt><dd>212</dd></div>
    <div><dt>Downlink today</dt><dd>14.2 TB</dd></div>
    <div><dt>State</dt><dd><void-state color="success">Online</void-state></dd></div>
    <div><dt>Site code</dt><dd data-void-type="code">SVB-1</dd></div>
  </dl>
</void-description-list>`;

export const gridErb = `
<void-description-list layout="grid" columns="4">
  <dl>
    <% @station.summary_pairs.each do |name, value| %>
      <div><dt><%= name %></dt><dd><%= value %></dd></div>
    <% end %>
    <div>
      <dt>State</dt>
      <dd><void-state color="<%= @station.state_color %>"><%= @station.state.humanize %></void-state></dd>

  </dl>
</void-description-list>`;

export const gridJsx = `
<void-description-list layout="grid" columns="4">

## Rows with a control

When each line is a thing with a control and not a name with a value (a setting with a switch, an event with a time), use `<void-rows>`. The text goes in `<void-row-text>`: a main line and a caption.

export const settings = `
<void-rows>
  <void-row>
    <void-row-text>
      <span>Accept passes automatically</span>
      <span data-void-type="caption">New passes are scheduled without review.</span>
    </void-row-text>
    <void-switch checked aria-label="Accept passes automatically"></void-switch>
  </void-row>
  <void-row>
    <void-row-text>
      <span>Weather hold</span>
      <span data-void-type="caption">Pause scheduling above 25 m/s wind.</span>
    </void-row-text>
    <void-switch aria-label="Weather hold"></void-switch>
  </void-row>
</void-rows>`;

export const settingsErb = `
<void-rows>
  <% @settings.each do |setting| %>
    <void-row>
      <void-row-text>
        <span><%= setting.title %></span>
        <span data-void-type="caption"><%= setting.description %></span>
      </void-row-text>
      <void-switch name="settings[<%= setting.key %>]" aria-label="<%= setting.title %>"
                   <%= "checked" if setting.enabled? %>></void-switch>
    </void-row>
  <% end %>
</void-rows>`;

export const settingsJsx = `
<void-rows>
  {settings.map((setting) => (
    <void-row key={setting.key}>
      <void-row-text>
        <span>{setting.title}</span>
        <span data-void-type="caption">{setting.description}</span>
      </void-row-text>
      <Switch
        checked={setting.enabled || undefined}
        aria-label={setting.title}
        onVoidChange={(event) => update(setting.key, event.detail.checked)}
      />
    </void-row>
  ))}
</void-rows>`;

<Example html={settings} erb={settingsErb} jsx={settingsJsx} />

`void-row-text` also works in a table cell, for a name with a line of detail under it.

### A state word and a control

The end of a row can hold more than one thing: put them in `<void-actions>`. A `<void-state>` beside a small button says what the thing is doing and offers the one action on it; they sit a tight gap apart on the row's centre line. When the last button is a `ghost` one, its label ends on the row's edge, in line with the values and switches of the other rows.

export const stateRow = `
<void-rows>
  <void-row>
    <void-row-text>
      <span>Svalbard 1</span>
      <span data-void-type="caption">X band, pass MRD-0412</span>
    </void-row-text>
    <void-actions>
      <void-state color="success" pulse>Tracking</void-state>
      <void-button variant="ghost" size="sm">Pause</void-button>
    </void-actions>
  </void-row>
  <void-row>
    <void-row-text>
      <span>Troll</span>
      <span data-void-type="caption">S band</span>
    </void-row-text>
    <void-actions>
      <void-state>Idle</void-state>
      <void-button variant="ghost" size="sm">Resume</void-button>
    </void-actions>
  </void-row>
</void-rows>`;

export const stateRowErb = `
<void-rows>
  <% @stations.each do |station| %>
    <void-row>
      <void-row-text>
        <span><%= station.name %></span>
        <span data-void-type="caption"><%= station.band %> band</span>
      </void-row-text>
      <void-actions>
        <void-state color="<%= state_color(station) %>"><%= station.state.humanize %></void-state>
        <void-button variant="ghost" size="sm"><%= link_to "Pause", pause_station_path(station), data: { turbo_method: :post } %></void-button>
      </void-actions>
    </void-row>
  <% end %>
</void-rows>`;

export const stateRowJsx = `
<void-rows>
  {stations.map((station) => (
    <void-row key={station.id}>
      <void-row-text>
        <span>{station.name}</span>
        <span data-void-type="caption">{station.band} band</span>
      </void-row-text>
      <void-actions>
        <void-state color={station.stateColor}>{station.state}</void-state>
        <Button variant="ghost" size="sm" onVoidClick={() => pause(station.id)}>Pause</Button>
      </void-actions>
    </void-row>
  ))}
</void-rows>`;

### A row with a tone

`color` on a `<void-row>` sets the line in a status colour: a warning in a log, a step that failed. Plain text takes the tone, and so does text in the `code`, `value` and `body` roles, so the line is one colour; a caption or a label stays quiet, and a control or a `<void-state>` keeps its own colours. The values are those of every `color` attribute. Each keeps 4.5:1 as text on the page and on every container, in both schemes and every skin. Say the level in words too (the message, or a `<void-state>`): colour must not be the only signal.

export const toned = `
<void-rows>
  <void-row>
    <span>Carrier lock on MRD-0412</span>
    <span data-void-type="code">14:02:11</span>
  </void-row>
  <void-row color="warning">
    <span>Warning: signal to noise below 5 dB</span>
    <span data-void-type="code">14:02:48</span>
  </void-row>
  <void-row color="error">
    <span>Error: carrier lost</span>
    <span data-void-type="code">14:03:05</span>
  </void-row>
</void-rows>`;

export const tonedErb = `
<void-rows>
  <% @events.each do |event| %>
    <void-row color="<%= LEVEL_COLORS.fetch(event.level, "default") %>">
      <span><%= event.message %></span>
      <span data-void-type="code"><%= l event.at, format: :clock %></span>
    </void-row>
  <% end %>
</void-rows>`;

export const tonedJsx = `
<void-rows>
  {events.map((event) => (
    <void-row key={event.id} color={LEVEL_COLORS[event.level] ?? 'default'}>
      <span>{event.message}</span>
      <span data-void-type="code">{event.at}</span>
    </void-row>
  ))}
</void-rows>`;

## Reference

| Element | Attribute | Values |
|---|---|---|
| `void-description-list` | `layout` | `rows` (default): label left, value right, a hairline between pairs. `grid`: label over value. |
| | `columns` | Rows: `1` (default) or `2`. Grid: `1` to `4`, default `2`. |
| | `justify` | Rows: `end` (default), the value at the end of its row; `start`, every value on one line after the label column. |
| `void-row` | `color` | `default`, or a status colour (`success`, `info`, `warning`, `caution`, `error`, `notice`, `highlight`): the row's text, and `code`, `value` and `body` text in it, take that colour. |

## Which one

- Names and values of **one record**: a description list.
- **Many records** with the same fields: a `void-table`.
- **One thing per line** with a control or a time: `void-rows`.
- **One number** that deserves attention: a [figure](/patterns/figure/).

## Why this form

It is CSS only and it wraps a real `<dl>` instead of taking `label` and `value` attributes on child elements. The list semantics come from the browser, values can be any markup, and the server renders plain HTML.
